============================================================
VISÃO GERAL
============================================================

OBJETIVO:
Criar um sistema de atendimento automático para estética automotiva com:

- WhatsApp via WAHA
- n8n
- OpenAI
- Supabase
- Atendimento com IA
- Confirmação do responsável
- Lembretes automáticos
- Check-in operacional: CHEGOU / FALTOU
- Relatório mensal no WhatsApp


ARQUITETURA:

WAHA
= conexão com WhatsApp

n8n
= automações e lógica dos workflows

OpenAI
= interpretação inteligente das mensagens

Supabase
= banco de dados / mini CRM

WhatsApp do responsável
= confirmação, lembretes internos, check-in e relatórios


RECOMENDAÇÃO:
Usar 1 VPS + 1 Supabase por cliente, para manter tudo isolado e profissional.


============================================================
1. CRIAR PROJETO NO SUPABASE
============================================================

1. Entrar no Supabase
2. Criar um novo projeto
3. Nome sugerido:

supabase-nomecliente-automotivo

Exemplo:

supabase-boy-veiculos-automotivo


============================================================
2. CRIAR TABELAS NO SUPABASE
============================================================

No Supabase:

Project
↓
SQL Editor
↓
New query
↓
Colar o SQL abaixo
↓
Run


SQL COMPLETO:

create table if not exists clientes (
  id uuid primary key default gen_random_uuid(),
  telefone text unique not null,
  nome text,
  draft_servico text,
  draft_veiculo text,
  draft_data text,
  draft_hora text,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

create table if not exists conversas (
  id uuid primary key default gen_random_uuid(),
  telefone text not null,
  nome text,
  direcao text,
  mensagem text,
  origem text,
  created_at timestamptz default now()
);

create table if not exists agendamentos (
  id uuid primary key default gen_random_uuid(),

  cliente_telefone text not null,
  cliente_nome text,

  servico text,
  servico_nome text,
  preco numeric default 0,
  preco_texto text,
  tempo_texto text,

  veiculo text,

  data_desejada text,
  hora_desejada text,

  data_confirmada text,
  hora_confirmada text,

  status text default 'PENDENTE_CONFIRMACAO_RESPONSAVEL',

  sugestao_data text,
  sugestao_hora text,
  sugestao_texto text,
  resposta_responsavel text,

  -- LEMBRETES — WORKFLOW 03
  lembrete_1h_cliente_enviado boolean default false,
  lembrete_1h_cliente_enviado_at timestamptz,

  lembrete_1h_responsavel_enviado boolean default false,
  lembrete_1h_responsavel_enviado_at timestamptz,

  lembrete_30min_responsavel_enviado boolean default false,
  lembrete_30min_responsavel_enviado_at timestamptz,

  -- CHECK-IN OPERACIONAL — WORKFLOW 05
  checkin_at timestamptz,
  faltou_at timestamptz,
  resultado_operacional text,

  confirmed_at timestamptz,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

create index if not exists idx_clientes_telefone
on clientes (telefone);

create index if not exists idx_agendamentos_status
on agendamentos (status);

create index if not exists idx_agendamentos_cliente_telefone
on agendamentos (cliente_telefone);

create index if not exists idx_conversas_telefone
on conversas (telefone);


============================================================
3. SE O BANCO JÁ EXISTIA ANTES
============================================================

Se você já tinha criado as tabelas antigas, não precisa apagar nada.

Rode apenas este ALTER TABLE para adicionar as colunas novas:

alter table agendamentos
add column if not exists lembrete_1h_cliente_enviado boolean default false,
add column if not exists lembrete_1h_cliente_enviado_at timestamptz,

add column if not exists lembrete_1h_responsavel_enviado boolean default false,
add column if not exists lembrete_1h_responsavel_enviado_at timestamptz,

add column if not exists lembrete_30min_responsavel_enviado boolean default false,
add column if not exists lembrete_30min_responsavel_enviado_at timestamptz,

add column if not exists checkin_at timestamptz,
add column if not exists faltou_at timestamptz,
add column if not exists resultado_operacional text;


REGRA SIMPLES:

Projeto novo:
usar SQL COMPLETO

Projeto já criado:
usar ALTER TABLE

============================================================
9. COMO FUNCIONA CADA WORKFLOW
============================================================

------------------------------------------------------------
WORKFLOW 01 — ATENDIMENTO IA
------------------------------------------------------------

Cliente chama no WhatsApp
↓
IA entende a mensagem
↓
Salva cliente no Supabase
↓
Salva conversa no Supabase
↓
Atualiza rascunho do atendimento
↓
Coleta serviço, veículo, data e hora
↓
Cria agendamento pendente
↓
Avisa o cliente
↓
Avisa o responsável


------------------------------------------------------------
WORKFLOW 02 — CONFIRMAÇÃO DO RESPONSÁVEL
------------------------------------------------------------

Responsável responde:

SIM

ou:

NÃO, disponível 10/05 às 14:00


Se responder SIM:

- status = CONFIRMADO
- cliente recebe confirmação


Se responder NÃO:

- sistema salva sugestão de novo horário
- cliente recebe sugestão


------------------------------------------------------------
WORKFLOW 03 — LEMBRETES AUTOMÁTICOS
------------------------------------------------------------

Roda a cada 10 minutos.

1 hora antes:

- envia lembrete para o cliente
- envia lembrete para o responsável
- inclui link clicável do WhatsApp do cliente

30 minutos antes:

- envia alerta interno para o responsável
- mensagem de “cliente chegando”
- inclui link clicável do WhatsApp do cliente


Formato do link:

https://wa.me/55DDDNUMERO


Flags anti-spam usadas:

- lembrete_1h_cliente_enviado
- lembrete_1h_responsavel_enviado
- lembrete_30min_responsavel_enviado


------------------------------------------------------------
WORKFLOW 04 — RELATÓRIO MENSAL / AVANÇADO
------------------------------------------------------------

Roda todo dia 1 às 09:00.

Calcula o mês anterior.

Métricas:

- agendamentos confirmados
- clientes únicos
- serviços simples
- serviços detalhados
- receita simples
- receita detalhada
- receita total
- ticket médio

Se usar o Workflow 05, também pode mostrar:

- clientes que compareceram
- clientes que faltaram
- taxa de presença
- taxa de falta


------------------------------------------------------------
WORKFLOW 05 — CHECK-IN OPERACIONAL
------------------------------------------------------------

Webhook:

automotivo-checkin-responsavel


Comandos do responsável:

CHEGOU

ou

FALTOU


Se responder CHEGOU:

- status = CLIENTE_CHEGOU
- salva checkin_at
- salva resultado_operacional = CHEGOU


Se responder FALTOU:

- status = CLIENTE_FALTOU
- salva faltou_at
- salva resultado_operacional = FALTOU
